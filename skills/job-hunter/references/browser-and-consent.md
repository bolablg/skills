# Browser, credentials, and consent

## Tool selection

Prefer purpose-built job, email, or browser connectors when they are authorized and preserve clear receipts. Otherwise use the host's Computer Use/browser capability. In Codex, follow the installed Computer Use Skill rather than assuming one fixed API. In hosts without browser control, research and prepare packets but do not claim submission or outreach.

Read-only search, page inspection, and drafting can proceed without external mutations. Creating accounts, logging in, transmitting candidate data, uploading files, submitting forms, or sending messages must follow the host's current confirmation policy and the exact approved batch.

## Credential handling

- Prefer an already authenticated browser session or password-manager autofill.
- Resolve secret references only at the destination that needs them.
- Never print, paste into chat, log, screenshot intentionally, or persist credentials in reports.
- If the host cannot inject a secret without revealing it, ask the user to take over.
- Account creation requires action-time confirmation; password changes require user handoff.
- CAPTCHA, MFA, recovery codes, identity verification, and security warnings require handoff or the confirmation required by the host.

## Sensitive-data transmission

Before typing or uploading, identify the exact data, destination, and purpose. The batch should name the résumé, contact data, eligibility answers, and any optional disclosures. A redirected domain, new document, or new sensitive field requires new approval.

## Platform boundaries

- LinkedIn: no third-party automation, scraping, connection requests, or automated messaging. Draft and hand off.
- Indeed: no agent/bot access or automated applications without an officially permitted connector. Draft and hand off.
- Workday: treat as manual unless the applicable tenant offers an authorized interface or terms permitting automation.
- Public ATS feeds: use sanctioned GET endpoints for discovery; use hosted application forms, not employer API keys, for candidate submission.
- Other sites: inspect current terms and robots controls before automation; do not bypass rate limits, bot challenges, or access restrictions.

## Receipt quality

Record the strongest available evidence: visible confirmation text and URL, a deliberately captured screenshot without secrets, or an email receipt when authorized. A filled form or click is not proof of submission.
